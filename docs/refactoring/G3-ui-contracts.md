## 1. R01 共通の外枠とナビゲーション

### 1.1 構成

```
src/app/
  AppShell.tsx        通常画面の外枠（アイコン定義、<main>、共通ナビゲーション、Ctrl/Cmd+K、検索ダイアログの差し込み口）
  AppNavigation.tsx   ModeMenu を移したもの。モード切替・本文検索・RAG・戻り先の操作。props は mode / onMode / onSearch / onRag? / resume?
  app-navigation.css  knowledge.css から移した .mode-menu / .global-search / .global-rag（印刷では非表示）
  return-point.ts     出典から移動した後の戻り先（4 節）
```

- `AppNavigation` は API も Library / Wiki / 検索の状態も参照しない。`AppShell` は検索ダイアログを `renderSearch` で受け取り、Wiki と検索のコードを import しない。
- `features/Knowledge.tsx` の `ModeMenu` の再 export は廃止した（利用先は `App.tsx` の1箇所だけだった）。`features/knowledge.css` からナビゲーション用の規則を移した。
- 埋め込み入口 `src/embed/main.tsx` と共有の `viewer/DocumentViewer.tsx` は `src/app/` も `features/knowledge/` も import しない。`src/app/embed-boundary.test.ts` が相対 import を辿って確認する。単独編集画面（`src/editor/`）も共通外枠を使わない。

### 1.3 画面の寿命表（本文を二重に mount しない）

| 画面 | 寿命 | 理由 |
| --- | --- | --- |
| Library | 常に mount、非表示（`hidden`）で保持 | 絞り込み・選択・スクロール位置・フォルダー表示を文書閲覧や Wiki への往復で失わない |
| Wiki | 常に mount、非表示で保持 | 開いている記事・絞り込み・編集中の下書き、取得は非表示中は停止（R10） |
| 検索・RAG ダイアログ | 常に mount、閉じている間は入力と最後の結果を保持 | 検索語・選択・結果を保つ（4 節） |
| 文書ビューアー・図ビューアー・Excalidraw 画面 | `key=job.id` で、開くたびに作り直し、離れると破棄 | 文書の本文を二重に持たない。翻訳・解説は閉じると破棄（R11） |
| 画像の詳細 | 開いている間だけ | ダイアログ |
| 「資料が見つかりません」 | 該当するときだけ | 案内のみ |

`App.tsx` の冒頭コメントにも同じ表を置いた。閲覧位置の保持は変更していない（ビューアー内の位置は `initialUnit` と `locations`（モードごとの最後の位置）で従来どおり）。

### 1.4 戻る・ショートカットは 1 回だけ作用する

- 戻る（`App.back`）: 同じ描画で 2 回呼ばれても 2 回目は何もしない（`leaving` を route 変更で解除）。`history` の追加は 1 回。ダイアログの `cancel` と `close` が続けて来る画像の詳細でも同じ。
- Ctrl/Cmd+K: `document` に listener は 1 つ。他の処理が `preventDefault` 済みのキー（エディター自身の Ctrl+K）と、押しっぱなし（`repeat`）は開かない。アンマウントで解除する。
- 検証: `App.test.tsx`（Back を連続で押す、Ctrl/Cmd+K、listener 数、処理済みのキー、アンマウント後）。

### 1.5 印刷・全画面・狭い幅

- 印刷: アプリ画面は印刷対象ではなく、印刷は `PrintPreview` の専用 iframe（`print.html`）で行う。念のため `app-navigation.css` に `@media print` で共通ナビを非表示にした。
- 全画面: アプリは Fullscreen API を使っていない（`requestFullscreen` なし）。ブラウザーの全画面は同じレイアウト。
- 狭い幅: 共通ナビは `flex: none` の部品で、`.library-bar` は 1000px 以下で折り返す（`knowledge.css`）。ビューアーのツールバーは従来の高さ段階（850px: 80px、620px: 112px）と `overflow-x: auto` を使う。出典から来たときの「戻り先」ボタンは資料一覧・Wiki のヘッダーにだけ出し、ビューアーのツールバーには増やさない（ビューアーは戻るボタンの名前を変える）。実機での 390×844 の到達確認は未実施。

## 3. R03 操作の優先順位と用語

### 3.1 操作用語表

| 用語 | 意味 | 対象 | 影響 | 取り消し |
| --- | --- | --- | --- | --- |
| 保存 | 管理対象を更新する（Wiki 記事、図表の版、画像の属性、翻訳等の下書き確定） | 開いているその対象 | 新しい版／更新。保存後の版が正本 | 図表は版の履歴から復元。Wiki・画像属性は再編集で上書き（版の戻しなし） |
| 原本を保存 | 登録時の原本のバイトをそのまま取得する | その資料（図表・Wiki 記事は保存済みの最新版） | ファイル取得のみ。管理対象は変えない | 不要（副作用なし） |
| 書き出し | 別形式・別ファイルを生成して取得する（SVG/WebP/JPEG/HTML、解説の Markdown/JSON、編集中の内容の .excalidraw） | 画面に出ている内容 | 取得のみ。管理対象は変えない | 不要 |
| 削除 | 既存の削除契約（確認なしですぐ実行。フォルダーは配下をサーバー側で扱う） | 選択した項目（資料一覧）、開いている記事（Wiki） | 一覧・検索から消える | 不可（資料一覧は確認ダイアログなし。契約は変更していない） |
| 破棄 | 保存していない画面上の入力・下書きを捨てる | 未保存の編集内容（図表の下書き、Wiki の編集中） | 画面の入力のみ。保存済みの内容は変えない | 不可 |
| 印刷・PDF保存 | ブラウザーの印刷画面で紙／PDF にする | プリントプレビューの内容 | 管理対象は変えない | 不要 |

資料一覧の削除に確認を付けるかは別の判断（契約変更）として残した。今回は結果の文面に対象名を入れ、ボタンの `title` で影響を示すにとどめた。

### 3.2 配置規則

| 区分 | 見た目 | 置く場所 | 例 |
| --- | --- | --- | --- |
| 主要 | `primary`（1 つの帯・ダイアログに 1 つ） | 帯の中で最後のグループ、ダイアログでは右端 | 資料を追加、保存、Wikiに保存、ここに移動 |
| 補助 | 既定のボタン、メニュー項目 | 主要の前。まれな操作は「…」（`DisclosureMenu`）へ | 名前を変更、移動先、版の履歴 |
| 危険 | `danger`（文字色 `--danger`） | 同じ帯・メニュー・ダイアログの最後。確認がある場合は確認側にも付ける | 削除、記事を削除／削除する、下書きを破棄、破棄して戻る、破棄する、最新版を読み込む（編集中の内容は破棄） |
| 閉じる・キャンセル | 既定 | ダイアログの主要の左 | 閉じる、キャンセル |

- 処理中は二重送信を防ぐ（`useOperationLock`、`busy`、`leaving`）。処理中に閉じられない条件（`Dialog busy`）は変更していない。
- 無効化の理由: 状態表示（`StatusMessage` の `kind`）で示せる所はそこに、ボタン単体は `title`（資料一覧の選択ツールバー、図表の保存・原本を保存）。無効なボタンはキーボードで届かないため、重要な理由は状態表示側に残す。
- 完了・失敗・処理中: 資料一覧の結果欄は、操作中は `running`（「処理しています…」）、失敗は `error`、成功は通常の status にした（失敗の文と一致するときだけ error）。

### 3.3 主要画面の適用一覧

| 画面 | 変更 |
| --- | --- |
| 資料一覧 | 名前変更ダイアログの確定ボタン「保存」→「名前を変更」（見出しと同じ動詞）。削除の結果に対象名（`「name」を削除しました。`／`N件を削除しました。`）。選択ツールバーの削除に影響を示す `title`、名前を変更・原本を保存の無効理由 `title`。処理中・失敗の状態表示 |

## 4. R05 出典から原本へ移動する導線

### 4.1 参照が持つ識別子

| 起点 | 対象の識別子 | 位置 | 版 | 実装 |
| --- | --- | --- | --- | --- |
| 検索結果（`SearchResults`） | Wiki: `source_id`（ローカルの記事 ID）／資料: `job_id`（ローカルの資料 ID） | Wiki: `locator.anchor`／資料: `unit` | 持たない。出典が更新されたかはサーバーが `output.stale` で返す | `hitTarget` → `SourceTarget` |
| RAG の引用（`[S1]`） | 同上 | 同上 | 同上 | 同上 |
| Wiki の関連資料ボタン | `related_document.job_id` | `source_unit`（なければ 1） | 持たない | `onReference({kind:"document"…})` |
| Wiki 本文内のアプリ内リンク | URL の `source`／`job` | `section`／`unit` | 持たない | `linkTarget` で解析、他のリンク（外部・修飾キー・別タブ）は従来どおり開かない |
| 表の「原本プレビューを見る」 | 同じ資料 | 表の最初のページ | — | 画面内（`selectPage`）。URL は `view` の置換のみ |
| 解説 | 同じ資料 | `source_match` のときだけ位置へ移動 | — | 画面内。Web 補足リンクは別タブ（参照ではない） |
| 埋め込み | `DocumentReference`（source_id、source_revision、evidence_revision） | `location` | **持つ**（セッション側で照合） | 変更なし（本節の対象外） |

ローカルの `job`／`source` と外部 API の識別子は同一視しない。`SourceTarget` はローカルの ID だけを表す。

### 4.2 URL で表す位置と、画面内に保持する戻り状態

| 区分 | 内容 | 保存先 | 再読込・直接 URL |
| --- | --- | --- | --- |
| URL（公開形式は変更なし） | `mode`、`source`、`section`、`job`、`view`、`unit`、`folder`、`library_scope`、`library_view` | `location` | 維持される |
| 戻り先（`ReturnPoint`） | 参照をたどる前の route、開いた出典、起点（検索／記事） | メモリ（`App` の state）。URL にも保存形式にも入れない | 失われる（直接 URL・再読込・別の出典を表示中は戻り先なし） |
| 検索の状態 | 検索語、方法・対象・範囲、最後の結果（取得の ID）、開いたリンク、結果のスクロール位置 | `KnowledgeSearch`（常に mount） | 失われる |
| 一覧・Wiki の位置 | フォルダー、絞り込み、選択、記事、スクロール | Library・Wiki（非表示で保持） | URL 分は維持 |

戻り先は、現在の route が戻り先の出典と同じ資料／記事を表示している間だけ有効（`activeReturn`）。出典内のページ移動では維持し、別の出典やモード切替では無効になる。

### 4.3 移動契約

| 操作 | 結果 |
| --- | --- |
| 検索結果／引用／関連資料／本文リンクをクリック | `follow(target, origin)`: 戻り先を記録し、`targetRoute` で移動（履歴に 1 つ追加）。ダイアログは閉じ、開いたリンクを記録 |
| 出典の戻る（ビューアーの `#backToFiles`） | 戻り先が有効なら戻り先の route へ（名前は「検索結果へ戻る」／「元の記事へ戻る」）、起点が検索なら検索を再表示。無効なら従来どおり資料一覧（`openedFrom` のフォーカス復帰を含む）。いずれも 1 回だけ作用 |
| 記事（Wiki）側から | 共通ナビに戻り先ボタン（「検索結果へ戻る」／「元の記事へ戻る」）。押すと戻り先の route へ |
| 起点の画面に戻った（ブラウザーの戻る・同じ URL） | 共通ナビに「検索結果を開く」。押すと検索を最後の結果とともに再表示（戻り先ボタンは出典を表示していないので出ない） |
| 検索の再表示（`resume`） | 検索語・選択・結果・開いたリンクの印（`data-opened`）・結果のスクロール位置を保ち、開いたリンクにフォーカス。通常の「本文を検索」は従来どおり新しい検索（結果は空） |
| ブラウザーの戻る／進む | `popstate` で route が戻る。戻り先は記録のまま（有効かどうかは route と照合） |
| 直接 URL・再読込 | 現在の契約どおり URL の位置を表示。戻り先・検索結果は復元しない（資料一覧へ戻る） |
| 位置が資料の範囲外（`unit` > ページ数） | ページ・スライド・シート型の資料では、最後の位置を表示していることを `viewer-message` に出す（黙って移動しない）。DOCX・TeX など 1 単位の資料は対象外 |

### 4.4 不可の参照

| 状態 | 表示（R04） | 他の資料への置換 |
| --- | --- | --- |
| 資料が見つからない（削除・権限の変更）と検索結果で出典が更新済み | `stale`:「資料が見つかりません。資料一覧へ戻って選び直してください。」＋補足。戻り先があればその名前のボタン。検索結果側の既存の「出典が更新されました。検索をやり直してください。」（`stale`）は維持 | しない |
| Wiki 記事が 404／410 | `stale`:「この記事は見つかりません。」＋補足、再読込は出さない | しない |
| Wiki 記事が 401／403 | `error`:「この記事を閲覧する権限がありません。」、再読込は出さない（401 は従来どおりログインへ） | しない |
| その他の失敗 | `error` と「再読み込み」（従来どおり） | しない |

見出し（`section`）が記事に存在しない場合の案内は未実装（記事は先頭のまま）。後続の課題として残す。

## 5. R18 機能別診断の表示（画面側）

- 取得: `GET /api/diagnostics/features`（`lib/diagnostics.ts`）。資料一覧の「機能の利用状態」ボタンでダイアログを開いたときと、「もう一度確認」を押したときだけ。タイマー、フォーカス、再接続の再取得はなし（`gcTime: 0`、`staleTime: 0`、`refetchInterval: false`）。通信は 認証・副作用なし・外部要求なしのサーバー契約に従う。

| --- | --- | --- |
| `available` | 種類なしの通常表示「利用できます」 | status |
| `not_configured` かつ `optional` | `setup`「未設定です（任意）」＋復旧手順。要約では数に含めず、「使わなければ対応は不要です」 | status |

| 取得失敗 | `error` と「もう一度確認」 | alert |

### 6.3.1 レビュー指摘への対応（契約）

- 図表キャンバスが描画中に例外を出して「もう一度読み込む」で作り直すときは、開いた時点の `initialScene` ではなく直前の編集中のシーン（`s.current`）から開き直す。作り直したキャンバスが最初に報告する状態は編集として扱わず、`s.current`・基準・下書きの送信は変えない（古い内容を下書きに送らない）。Wiki エディターの親は常に最新の本文を `initial` に渡すため、文面のみ調整した。
- 画像属性の保存: `412`（ETag 不一致）と `428`（If-Match なし）は版の競合として「最新情報を読み直す」を出す。`409`（同名）は通常のエラーで入力を保つ。
- Wiki の変更系操作（取り込み・削除）の排他は、リクエストが終わるまで解除しない。画面や記事を移った後も実行中の要求は続くため、その間の同じ操作は無効。結果は現在の画面のものでなければ捨てる。
- Wiki 記事が 404/410 のときは定期取得を止め、以前の本文を残さず「見つかりません」だけを表示する。削除成功後はその記事のキャッシュを破棄する。
- 検索タスクの定期取得は `output` が無い間も古い扱いにしない（`output?.stale`）。
