## R01 共通の外枠とナビゲーション

**工程G3、優先度P1、規模M、依存R04 R06 R07。評価軸は設計・操作性。**

変更箇所は `frontend/src/App.tsx`、`features/Knowledge.tsx`の`ModeMenu`、`features/Viewer.tsx`、`Library.tsx`、図編集の外枠。既存のButton・Toolbarとルート管理を使う。配置案は `frontend/src/app/AppShell.tsx` と `AppNavigation.tsx`。

1. 現在のヘッダー、現在地、戻る、検索、RAG、資料追加の配置と表示条件を一覧化する。原本固有のツールバーとアプリ操作を区別する。
2. `ModeMenu`をWikiの責務から外し、ルート・イベントを受け取る共通ナビゲーションへ移す。API取得や資料操作は入れない。
3. 通常画面だけを共通外枠に接続する。本文を二重にmountしないよう、非表示維持が必要な画面と破棄できる画面を明記する。既存の閲覧位置保持を引き継ぐ。
4. 文書の印刷、全画面、狭い画面で外枠が本文領域を塞がないようにする。埋め込み入口は共通外枠をimportしない。

受入条件は、資料一覧・Wiki・原本・図編集で主要入口と現在地が一貫し、戻る操作とショートカットが1回だけ作用すること。原本iframeの内容・sandbox、埋め込みのDOMに変化を加えない。`App.test.tsx`、`Viewer.test.tsx`、Wiki・operations・diagramの該当操作で確認する。

切り戻しは外枠への接続を差分単位で戻す。ルート形式やデータ移行を伴わせない。成果物は共通外枠、配置表、更新した共通部品台帳と操作記録。

## R10 取得と更新通知の規則

**工程G1、優先度P2、規模M、依存R09。評価軸は性能・正確性。**

変更箇所は `App.tsx`、Wiki・検索・Translation・Explanationのquery、図編集後の一覧更新。既存TanStack Queryを使い、配置案は機能別query定義と `src/lib/query-keys.ts`。

1. 取得キー、取得条件、処理中・待機中・非表示時の間隔、失敗時の扱い、更新後の無効化先を表にする。
2. libraryの常時2秒（`App.tsx`）、Wikiのcatalog・記事の5秒、検索dialogを開いている間の `knowledge-status` の2秒、検索受付の終了まで続く2秒、翻訳・解説の状態に応じた取得（いずれも `features/` の各画面）を、可視性・サーバー上の実行状態・利用目的で整理する。
3. 同じ資料・版・設定のquery keyを揃え、保存・移動・削除・翻訳・解説の完了時に必要な取得だけ無効化する。別の全体state storeや新しいpush配信は導入しない。
4. 別クライアントの更新も拾う低頻度確認とonline復帰を残す。非表示にしたために受理済み処理を見失わないようにする。

提案する受入値は、60秒待機時の要求数を同じ条件の基準比50%以上削減、可視画面の外部更新検知を10秒以内、処理中は従来の通知遅延を悪化させないこと。G0で入力・計測方法を固定し、互換性に問題があれば実装前に値と理由を更新する。失敗後の取消・明示再試行も確認する。

切り戻しはqueryごとの取得方針を戻す。成果物は取得方針表、query定義、要求数と更新遅延の比較。
