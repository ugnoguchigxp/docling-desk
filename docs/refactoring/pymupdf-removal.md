# PyMuPDF（AGPL）の除去と原本プレビューの再設計

2026年10月21日。ライセンスをMIT/Apache-2.0と両立するものに限る方針のため、AGPL-3.0のPyMuPDF（`pymupdf`、MuPDF）を製品コードと試験から完全に外す。代わりにApache-2.0/BSDの`pypdfium2`（PDFium）とMITの`python-pptx`を使う。

## 理由

- PyMuPDFはAGPL-3.0（商用ライセンスは別契約）。ネットワーク越しに提供するDocling Deskに組み込むと、対応ソースの提供義務が配布物全体に及び得る。所有者がMIT/Apache-2.0と両立するライセンスだけを許可するため、依存から外す。
- `pypdfium2`はApache-2.0またはBSD-3-Clause。Doclingが既にPDFiumを使っており、`docling.utils.locks.pypdfium2_lock`でPDFiumの同時利用を直列化している。この錠を引き続き使う。
- `python-pptx`はMIT。PPTXの文字枠座標は従来どおりここから取る。
- `fonttools`はPyMuPDFのPDF内フォント抽出専用の用途で使っていた。この用途がなくなるため、他に使う箇所が残らなければ依存から外せる（pyproject等は担当外。末尾の「依存物の変更」を参照）。

## 旧実装が使っていたPyMuPDF固有機能

`preview/editable_preview.py`がPDFページをSVGへ再構成していた。

| 機能 | 用途 |
| --- | --- |
| `page.get_svg_image` | ベクター図形と文字をSVG化 |
| `page.get_texttrace` | 文字ごとの位置・フォント・色・合字 |
| `page.get_fonts` / `extract_font` | PDF内のサブセットフォントを取り出し、`@font-face`としてSVGに埋め込む |
| `page.get_text("dict")` | PDFの文字ブロック |
| 上記を使う`translation/svg.py` | 訳文差し替え後に、SVGの文字位置を折り返さず流す |

PDFiumにはこれらに相当する機能がない（SVG出力なし、フォント抽出なし）。同じ表現は他のMIT/Apache-2.0部品でも得られない。

## 新しい設計（所有者承認済み）

### 原本プレビュー

1. PDFの各ページをPDFiumで画像（WebP）に描画する。ベクター図形も文字も画像に焼き込まれる。
2. その上に、見えない文字層を重ねる。文字層はPDFiumの`PdfTextPage`（文字ごとの外接矩形・フォントサイズ・基線方向）から作る。画像上の文字を選択・コピー・検索できる。SVGの文字再構成とフォント抽出は行わない。
3. 文字層は行を段落ブロックへまとめた`div.pdf-text`で、1ブロックに1つのテキストノードを持つ。ブロックはページ幅に対する百分率で配置し、フォントサイズは`cqw`単位で指定するので、iframeの大きさが変わっても画像と一緒に拡縮する。
4. PPTXは従来どおりPowerPoint/LibreOfficeでPDFへ書き出し、同じ経路でPDFのページ画像と文字層にする。`source_textboxes`（python-pptx）が持つ図形・グループ・表セルの座標を、文字ブロックの位置にそのまま使う。PDFの文字は、その文字枠内のフォントサイズ・色・背景色を決めるために使う。どの文字枠にも入らないPDF上の文字（スライドマスタ由来のフッターなど）は、PDF由来のブロックとして追加する。

### 訳文表示

- 訳文は、原文の文字ブロックの位置に重ねて表示する。`translation/view.py`の`apply_text`が、ブロックのテキストを訳文に置換し、`data-translated`を付ける。CSSがそのブロックだけを不透明（背景が一様でないときは不透明度0.88）の背景色と文字色で表示し、元の文字を隠す。
- 背景色はページ画像のブロック領域の最頻色、文字色はPDFの文字色（取れなければ背景に対する白黒）。
- 文字サイズは、枠の幅・高さに収まるまで、全角・半角の幅を仮定した折返し計算で縮める。最小は元のサイズの55%。それでも収まらない場合ははみ出して表示する（隠さない）。
- 訳文の区切り（セグメント）は、これまでの「SVGの文字片ごと」から「文字ブロックごと」に変わる。ブロックは行を改行で結んだ文字列で、文の途中で切れた断片を別々に訳すことは減る。IDは`t00001`形式を維持する。
- 位置を決められないとき（プレビューがない、文字ブロックがない）は、従来の「別枠」表示（`mode: panel`）になる。別枠は原文と訳文を並べた2列の一覧に変わる。

### 旧版で作った訳文

セグメント構成が変わるので、旧版の保存済み訳文は`source_hash`が一致しなくなり、既存の「古くなった（stale）」状態になる。画面では「原文が更新されています」と表示され、「翻訳をやり直す」から再実行できる。ただし訳文は消さない。

- 旧版の展開データ（`translation-source.json`）を作り直す直前に、旧版のまま`translation-source.legacy.json`へ退避する（`renderer_version`が違う場合に限る）。退避は`source_hash`をキーに追記するだけで、切り戻し後に再度アップグレードしても、世代ごとの原文が残る。退避に失敗した場合は警告を記録して本体の更新を続ける（訳文ファイルは変更しないので失われない）。
- 訳文の状態取得は、stale状態の訳文が退避した旧セグメントと一致するとき、原文と訳文の対応一覧（`pairs`）を返す。画面は、位置に置けないこの訳文を、原文/訳文の2列一覧として側面パネルに表示する。
- 再翻訳すると新しい文字ブロックの位置に表示される。退避ファイルは消さない（再生成できない利用者データの手がかりのため）。

## 保存データの移行・旧版読出し・切り戻し

| 対象 | 新版の扱い |
| --- | --- |
| `editable-preview/`（`manifest.version` 3以前） | `RENDERER_VERSION`を3から4へ上げた。版が違うマニフェストは「無効」とみなし、描画には一切読まない。要求が来たとき（PDFのプレビュー取得、PPTXのスライド取得、翻訳展開）に、原本PDFまたは保存済み`powerpoint-rendered.pdf`から作り直す。作り直しの公開は、完成したディレクトリを入れ替える従来の方式で、旧ディレクトリは入れ替え後に消える（再生成できる派生物のため）。旧版の資料を一括で消すことはしない。 |
| `slides.json`の`preview` | スライドごとのパス名（`editable-preview/page-N.html`）は変わらない。パスを書き換える必要はない。 |
| `powerpoint-rendered.pdf` / `powerpoint-export.json` | そのまま使う。旧`editable-preview/manifest.json`がPDFの検証済み記録として残っているときは、従来どおり検証済みの書き出しとして受け入れる（ハッシュだけを読む）。 |
| PPTXで保存済みPDFもOffice書き出しも使えない | プレビューを読めない扱い（`preview_unavailable_reason`）になり、別枠表示に切り替わる。`python -m docling_desk.preview.preview_migration --saved-pdf-only`で個別に作り直せる。 |
| `translation-source.json` | `dependencies.renderer_version`が違うので作り直される。旧版は上記のとおり退避。 |
| `translations/` | 変更しない。新版の訳文は新しいセグメントIDと`source_hash`で保存される。 |
| ページ画像プレビューを使わない資料（Word、Excel、画像等、およびプレビューが`editable-preview/`でないPPTX） | 展開データに記録する描画方式の版を3のまま保ち、保存済み訳文を古くしない。版を上げたのは、PDFと、`editable-preview/`で表示するPPTXだけ。 |
| PPTXで旧プレビューがあり、保存済みPDFもない | プレビューは読まず、翻訳状態は`preview_unavailable_reason`付きの別枠表示になる。スライドの表示は理由付きの404を返す。 |

切り戻し（PyMuPDF版へ戻す）: 旧版は版4のマニフェストを「版が違う」として無視し、`editable-preview/`を自分で作り直す。`translation-source.json`も依存の版が違うので作り直す。新版で保存した訳文は旧版ではstaleになり、再翻訳で戻る。`translation-source.legacy.json`は旧版が読まないので害はない。削除や書き換えを要する手順はない。

## 失う品質

- 原本と同じフォントでの置換: 旧版はPDF内のフォントを取り出して訳文以外を保ち、訳文もSVGの文字として原位置に置き換えた。新版は画像に焼き込まれた原文の上に、Web標準フォント（Arial、ヒラギノ、游ゴシック等）の訳文を重ねる。フォント・字間・文字の太さは原本と同じにならない。
- ベクターの文字・図形: 旧版は拡大しても文字と図形がベクターだった。新版は画像（最大約2倍、長辺3200px以内）なので、高倍率では粗くなる。
- 訳文の背景: 元の文字を隠す背景色はブロック領域の最頻色なので、グラデーションや写真の上の文字では、色が揃わない帯が見えることがある。
- 位置: 訳文の折返しは仮定の文字幅で決めるため、実際の文字幅と合わないことがある。90度単位でない回転（斜めの文字）はブロックにしない（原本の画像のまま、選択も翻訳もできない）。90度単位の回転と、ページ自体の`Rotate`は扱う。縦書き（字形を縦に積む書き方）は行として正しくまとまらないことがある。
- 表示環境: 文字層の大きさにCSSのコンテナ単位（`cqw`）を使うため、Chrome 105、Safari 16、Firefox 110以降が必要。
- PPTXでスライドマスタ由来の文字は、PDF由来のブロックで追加するが、PDFの行まとめに依存する。
- 速度: 旧版は文字ごとにSVG・フォントを作っていた。新版は描画が主な処理時間になる。

## 暗号化PDFの扱い

拒否するのは、開くのにユーザーパスワードが必要なPDF（PDFiumが「パスワードが違う」を返すもの）です。旧版（`needs_pass`）と同じ基準です。ユーザーパスワードが空で所有者パスワードだけを設定したPDFは、そのまま読めるので受け付けます。これも旧版と同じ挙動で、意図したものです。ナレッジ用ワーカーの検証は、ページを読まずに件数と暗号化だけを確認します。

## 守る契約（変更なし）

- iframeの`sandbox`とCSP。ページHTMLは外部要求をしない。画像は同じ資料フォルダ内のファイルだけを参照する。`slide_template`が、フォルダ外の参照を除去する仕組みはそのまま。
- ページ数の上限`MAX_PAGES`、暗号化PDF（ユーザーパスワードが必要なPDF）の拒否、PDFiumの`pypdfium2_lock`、プレビュー生成の`PDF_RENDER_LOCK`。
- 生成中に原本またはPDFが変わったら公開しない。完成したディレクトリの入れ替えで公開する。訳文の退避ファイルは`atomic_files`経由で書く。ページ画像の再生成は翻訳の全体ロックの外で行い、ロックを取り直してから依存を再計算・検証する。
- 原本バイト、資料ID、保存済み翻訳を変更・削除しない。

## 試験

- どの`docling_desk`モジュールもPyMuPDF/fitzを読み込まないこと: `sys.modules['pymupdf'] = None`・`sys.modules['fitz'] = None`にして全モジュールを読み込む試験と、ソース全体の文字列検索（`tests/test_no_pymupdf.py`）。
- 試験の作成物も`pymupdf`を使わない（`reportlab`、`pypdfium2`）。

## 依存物の変更（担当外、監督者が反映）

`pyproject.toml`、`requirements-lock.txt`、`NOTICE.md`、`supply/**`から`pymupdf`を外す。他の用途が残らなければ`fonttools`も外せる。詳細は完了報告に記載。
