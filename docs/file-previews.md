# 画像・テキスト・TeX・draw.ioの取込みと閲覧

資料一覧の「資料を追加」、またはファイルのドラッグ＆ドロップから取り込む。保存先、原本ダウンロード、一覧での移動・コピー・削除は既存の資料機構を使う。1ファイル50 MiBまで。

| 形式 | ビューアー |
| --- | --- |
| PNG / JPEG / GIF / WebP | 全体表示、100%、拡大・縮小、スクロール・ドラッグ移動。GIF/WebPのアニメーションも原本で表示 |
| TXT / TEXT | 行番号、本文検索（大文字・小文字を区別）、一致箇所への移動、折り返し、文字サイズ |
| TeX / LaTeX | 組版したPDFとソース表示を切替。組版PDFはページ移動・サムネイル・倍率・幅合わせを持つ既存のPDFビューアーを利用 |
| draw.io | 図だけを表示。ページ切替、拡大・縮小、全体表示、ドラッグ移動、レイヤー切替 |
| Markdown | 既存の本文プレビュー。見出し・表などを整形して表示 |

## TeXの導入条件

[Tectonicの公式導入手順](https://tectonic-typesetting.github.io/book/latest/installation/)に従い、`tectonic`をアプリ起動時のPATHに配置する。macOSでは `brew install tectonic` で導入できる。macOSの実行分離にはOS付属の`/usr/bin/sandbox-exec`、Linuxには`bubblewrap`（`bwrap`）が必要。DockerイメージにはTectonicを含めていない。コンテナで組版する場合もTectonicの追加と、ホストでのbubblewrap用ユーザー名前空間の利用許可が必要になる。

Tectonicは初回と未取得パッケージの使用時に組版用のファイルを取得する。アプリの共有キャッシュ配下`tectonic/`へ保存するため、初回はネットワーク接続が必要。アプリの認証キー等の環境変数は組版プロセスへ渡さない。組版には120秒の制限があり、初回取得が間に合わなかった場合は、ネットワークを確認して同じファイルを再取り込みする。取得済みパッケージは次回に再利用する。

対象は単独で組版できるTeXファイル。外部の画像・別TeX・独自クラス・参考文献ファイルをまとめて取り込む機能は含まない。Tectonicで利用できるLaTeX/XeTeXのパッケージとフォントに従う。日本語ではXeTeXに対応する文書設定・フォントを使用する。pLaTeX専用の文書を自動変換しない。

TeXソースは元の文字を保存・表示し、既存の文書抽出・検索機構へ接続する。独自の正規表現でTeXコマンドを文章へ変換しない。組版結果は派生成果物`tex-preview.pdf`であり、元ファイルを置き換えない。組版失敗時は「一部完了」と理由を表示し、ソース表示・検索・原本ダウンロードは利用できる。

## 実行と安全境界

[公式のuntrustedモード](https://tectonic-typesetting.github.io/book/latest/v2cli/compile.html)でshell escapeを無効にし、さらにOSの分離機構で原本をコピーした一時作業領域・組版キャッシュ・必要なシステム資源へのアクセスに制限する。分離機構が使えない環境では組版を実行せず、ソース表示へ戻す。一時作業領域には利用者の他の資料を配置しない。HTMLを含むテキスト・TeXはエスケープして表示する。

## 実装範囲と検証

画像・テキストの保存、画像の属性編集、PDFの描画・ページ操作は既存機構を利用した。追加はTeXの形式登録、Tectonic呼出しとOS分離、組版状態の保存、PDF／ソース切替、画像操作とソース表示の操作に限る。LLMによる意味判断や既存の指示・ツールを代替する解析処理は追加していない。

部分検証は形式・保存・ソース文字の保持・組版失敗時の状態、結合検証はアップロードからPDFページ・サムネイル・ソース取得まで。実エンジンで2ページの組版と私有ファイル参照の拒否を確認する。ブラウザーでは画像操作、テキスト検索、TeXの組版／ソース切替、ページ移動を確認する。


## draw.ioの対応範囲

`.drawio`・`.dio`・draw.ioの`.xml`、図データを埋め込んだSVG・PNG、draw.ioから書き出したHTML（`.html`・`.htm`）に対応する。PNGは拡張子の前に`.drawio`がなくても埋込み図データから判別し、通常のPNGは画像として取り込む。PDF書き出しは既存のPDFビューアーで閲覧できる。任意のXML・SVG・HTMLをdraw.ioファイルとして取り込む機能ではない。HTMLは図データを1つ含む書き出しを対象とする。

圧縮・非圧縮のページを混在でき、日本語、複数ページ、標準の追加図形、埋込み独自図形、埋込み画像、数式、複数レイヤーを表示する。図の解釈・描画は公式の閲覧専用ライブラリに委ね、独自の図形描画や意味判断は追加していない。XMLの外部実体を禁止し、圧縮ページと埋込み図形は展開後も合計50 MiB以内か検査する。原本を変更せず保存する。

図のプレビューを開いたときだけ共通の閲覧ライブラリと標準図形集を読み込む。数式の描画資源は必要時に読み込む。図の描画資源は全資料で共有し、draw.ioのデスクトップアプリや編集画面は使わない。編集・翻訳・解説・本文抽出の操作は図の画面には表示しない。この追加はローカルの資料一覧と閲覧が対象で、外部ナレッジAPI/MCPの取込み形式は拡張していない。

外部URLの画像・フォント・図形定義は自動取得しない。参照資源を取得できない場合や未知の独自図形を代替表示した場合は理由を画面へ出す。外部資源を使う図は、必要な画像や図形定義を図データへ埋め込んで取り込む。すべての独自図形・外部サービスとの完全互換は保証しない。

## 保存容量と表示時のサイズ

合計の保存容量は「原本＋管理情報＋抽出・プレビュー成果物＋再生成用キャッシュ」。プレビュー単体が必ず原本より大きくなるわけではないが、原本を保持したまま成果物を追加する分だけ合計は増える。PDF・Officeでは、展開したHTML、ページ画像、フォント、抽出JSON、翻訳などの合計が圧縮された原本より大きくなることがある。

draw.ioは原本を読んで閲覧時にHTMLを組み立てるため、資料ごとのHTML、ラスタ画像、展開済み図データをディスクへ重複保存しない。追加の保存はページ数・種別などの管理情報が中心になる。共通の閲覧・図形・数式ライブラリは合計約10.4 MBをアプリへ一度だけ同梱し、資料ごとには複製しない。

保存容量と、表示時の通信・メモリ使用量は別。圧縮された図は表示時に展開するので、生成したHTML応答やブラウザー内のデータが原本より大きくなる場合がある。これは生成HTMLをディスクに蓄積することを意味しない。
