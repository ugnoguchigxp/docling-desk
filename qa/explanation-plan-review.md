方法: 主担当による文書レビュー、現行ソースとの照合、修正後の再レビュー。別チャットへのメッセージ送信やサブエージェントへの委任は行っていない。

## 判定

第1回と第2回で以下の問題を修正し、第3回で要件・状態・保存・画面・検証を再照合した。今回確認した範囲では、未解決の具体的な改善指摘は0件。

これは計画書のレビュー判定であり、機能の実装・接続・品質の検証完了を意味しない。生成サービス・検索サービスの選定や予算の確定は、実装準備段階の決定記録と進行条件として計画書に残している。

## 第1回: 設計の矛盾と抜けの修正

| ID | 指摘 | 修正内容 |
|---|---|---|
| R1-01 | ボタンで未作成時に生成するとしながら、表示操作では生成しないという境界が曖昧 | 明示クリックと、再読込・移動・状態取得を分け、初回クリックの送信説明を操作前に表示 |
| R1-02 | 翻訳用の文字候補判定を使うと、数字だけのセルなどを失う | 原文の段落・表構造・数字・空欄を直接保持し、図の除外範囲も定義 |
| R1-03 | 意味の欠落まで固定応答のテストで自動検出できるように読める | 構造検証、LLMの意味評価、人による導入時品質確認を分け、判定不能を失敗にする |
| R1-04 | 原文とRAGを別時点で読むと入力が混在する | 読込前後と参照整合を確認した受付スナップショットを全処理に使う |
| R1-05 | SQLのパラメーター化だけではFTSの演算子解釈を防げない | リテラル語としてのFTS処理、短語検索の特殊文字、0件と親参照不整合を定義 |
| R1-06 | 索引作成中の公開、コピー時のDB付属ファイルの扱いが不明 | 一時DBで構築・検証後に置換し、コピーから索引・付属ファイルを除外 |
| R1-07 | 非公開固有語の公開性をモデルだけで保証する前提がある | 送信候補の検証・省略・管理設定による無効化と限界を明記 |
| R1-08 | RAGのIDを書き換えるコピーと、ファイルの生ハッシュ一致が両立しない | 資料ローカルIDへの正規化による内容ハッシュと読込用バイトハッシュを分離 |
| R1-09 | 最新版に参照されない過去版を未公開と判定すると公開済み版を削除し得る | 公開履歴を最新参照と一括確定し、未公開版・旧公開版・破損版を区別 |
| R1-10 | 現在の抽出データによる単位検証で、消えた単位の保存版を読めない | GETを現在単位と保存単位の和集合にし、原文欠落でも保存版を返す |
| R1-11 | ごみ箱の拒否や内部ファイルの非公開が既存ヘルパーだけで成立するとは限らない | 実効ごみ箱状態を専用APIで確認し、汎用ファイルAPIから内部データを除外 |
| R1-12 | 対象なし・重複・登録失敗・停止の状態と受付順が不十分 | `not_applicable`、受付順、同一要求再利用、枠解放、中断復旧を定義 |
| R1-13 | コピー・ごみ箱と受付の事前確認に競合がある | ロック順序と受付状態の公開、コピーの除外・ID対応・旧版の古さ保持を定義 |
| R1-14 | 時間、呼び出し、分割、保存の総上限が未定義 | 初期予算、再試行を含む総回数・期限、容量不足時の停止条件を追加 |

## 第2回: 修正後の境界条件の修正

| ID | 指摘 | 修正内容 |
|---|---|---|
| R2-01 | 論点整理1回という記述と、長文の各部分での整理が不一致 | 各部分1回、検索語上限は単位全体と定義。検索候補なしも記録 |
| R2-02 | 部分ごとに収まる長文でも、全体見直しの一括入力は上限を超え得る | 確認済みの論点・用語・数値条件と接続箇所を範囲付きで確認し、網羅未完了は失敗 |
| R2-03 | 古い状態バックアップからの復旧で、後から公開された版を消し得る | 復旧時の不明ファイルを自動削除せず、GETは復旧表示だけ。同期失敗とロック順も明記 |
| R2-04 | 接続の分離を指示文だけに依存すると、生成会話からの検索が発生し得る | 接続設定・能力・実行結果で検証し、Web側には検証済み検索語だけを渡す |
| R2-05 | 消えた単位をAPIで読めても、画面から開く導線がない | 「保存版のみ」の対象一覧と原本追従の区別を追加 |
| R2-06 | Webの成功・部分成功・根拠なしの判定が曖昧 | 本文確認の有無と補足対象ごとの結果に基づく集計条件を定義 |
| R2-07 | POSTの受入項目と、保存版なしのダウンロード応答が未定義 | `unit_id`・厳密な真偽値の`force`のみ、未知項目422、ダウンロード404と定義 |
| R2-08 | 空白の正規化が原文の意味を変える可能性がある | JSON整形だけを除き、文字列内の空白・順序・未知の意味フィールドを保持 |

## 第3回: 最終照合

次のケースについて、API、保存、画面、検証の記述を照合し、新たな改善指摘はなかった。

- 未作成、作成中、作成済み、対象なし、失敗、中断。
- 保存版の再閲覧、認証・生成設定の変更、ネットワークなしの取得。
- 再生成成功・失敗、版保存と状態確定の各地点での停止。
- 原文更新、原文欠落、単位消失、ハッシュ方式の変更。
- 改名、移動、コピー、古い版のコピー、ごみ箱と復元、受付との競合。
- FTS短語・特殊文字・ヒット0件、Web部分成功・根拠なし・管理設定での無効化。
- 長文分割、全体確認、総回数・時間・保存上限、登録失敗。
- 固定応答の通常検証と、実接続・人による品質確認の違い。
