# Wiki共通基盤の実装・テスト・レビュー

2026年10月6日。Docling Deskで、プロジェクト別の翻訳指示と旧ジョブの再開互換性、編集用ワークスペースの書き出し原本の閲覧を実装した。変更はDocling側だけで行い、差分を自己レビューし、指摘に対応する合成テストと全体の回帰検証を実行した。

## 調査結果

変更前のWikiバッチ・CSV目次・Wiki関連テストは38件成功。指示は汎用の定数を参照し、snapshotには指示本文を保存していなかった。原本へのリンクも登録済みWiki記事を中心に解決していた。

Samuraiの`api/translation/prompts.ts`と保存DB本体を読み取りで照合した。SQLiteは`mode=ro&immutable=1`で開き、WAL・SHM・ロックファイルへ書き込まない方法を使った。DB本体に保存された2,474ジョブは汎用指示では0件一致、Samuraiの現行8段階の指示では2,474件すべてのレシピハッシュが一致した。WALにある稼働中の最新状態はこの照合に含まない。指示には共通用語規則だけでなく、`resolve`にも透析分野の差分がある。

この照合はレシピの整合性を確認したもので、実ジョブの再開・翻訳成功を確認したものではない。実DB、資料、認証情報をDoclingへ移行していない。追加した旧形式fixtureの本文・単位は既存の合成fixtureを基にし、実資料を含めていない。

## 実装した機能

- `manifests/translation-instructions.json`または`--instructions`で8段階の指示を指定する。設定がない場合は既定の汎用指示を使う。全本文の指定と、共通用語規則を差し替える`termRules`形式に対応する。
- 新規ジョブには展開済みの指示、モデル、要求の入出力上限、調査上限、用語・調査処理版、入力、単位を保存する。再開時は保存した指示を使い、選択した設定、モデル、入力、対応表、レシピ、実行可能な処理条件の一致を確認する。
- 現行Samurai形式は登録時の8段階の指示を指定し、旧レシピハッシュを検証してから再開する。ハッシュ検査を無効化せず、保存済み入力・レシピハッシュを書き換えない。単位の再分割もしない。
- 旧形式の要求本文ハッシュも照合する。互換性を確認した調査、packet、成功応答を再利用する。旧ジョブの調査出力量と翻訳の最小出力量は旧ワーカーと同じ4,096トークンにする。
- ワークスペース同期により、そのワークスペースの`sources/`だけをローカルの原本参照領域へ登録する。移行処理はコピー先を登録する。
- 原本Markdown・CSVは別タブの読み取り専用画面、添付ファイルは元のバイトの取得に対応する。通常の資料登録・再変換は不要。登録済み記事を優先し、原本の下位フォルダー・日本語・空白・パーセント記号を含むリンクを扱う。
- 領域外・絶対パス・シンボリックリンク・通常ファイル以外を拒否する。ディレクトリを開いた状態でパスを辿り、描画後の欠落とリンクへの差し替えも確認する。参照できないリンクやファイルは利用者へ理由を表示する。

## レビューで修正した点

| 問題 | 修正と確認 |
| --- | --- |
| 公開復旧ではモデルや対応表の変更を十分に確認できなかった | 公開途中も指示・モデル・原文の対応・タイトル・分類・入力ハッシュを照合。公開候補と保存payloadを維持するテストで確認 |
| 旧ワーカーの要求記録は`term-input/call/`にあり、Python形式の記録だけでは照合できなかった | 保存した要求本文ハッシュとroleを再利用前に検査。一致時は成功応答を再利用、不一致時は送信も再利用も止める |
| 旧ワーカーとPythonワーカーで要求の出力量上限が異なった | 旧ジョブには従来の上限を適用。新規ジョブでは上限を保存し、不一致の条件を拒否する |
| 原本画面のCSPが既存の共通ヘッダー処理で上書きされた | 原本の経路に専用の制限を適用し、スクリプトを許可しない。APIテストとブラウザーで確認 |
| 欠落リンクにも別タブ用属性が付いていた | 開ける原本だけを別タブへ遷移させ、欠落リンクは現在の画面に理由を表示。ブラウザーで確認 |

再レビュー時点で、この範囲に未解決の重大な指摘はない。独立した第三者によるレビューは実施していない。

## コピー後の設定と未検証事項

設定形式・既存ジョブへの適用・現行Samurai指示のオフライン書き出し例は[Wikiバッチの手順](../../docs/wiki-batch.md)、原本リンクと登録領域は[Wikiの手順](../../docs/wiki.md)に記載した。

Samurai側へアプリをコピーした後は、退避した現行8段階の指示をコピー先ワークスペースの`manifests/translation-instructions.json`に置き、保存済みジョブと同じ下訳・検証のモデル名を設定する。コピー先の`--root`と画面保存領域の`--data`で`sync`を実行し、原本領域を登録し直す。`--instructions`で外部ファイルを使うなら登録時と再開時の両方に同じファイルを指定する。ハッシュ不一致を再登録や書き換えで隠さない。

資料群の対応規則、日本語タイトル、日英UI、CSV固有の画面、数値保留の後処理は今回の対象外であり、コピー後のSamurai側で設定・調整する。実データ移行、稼働中バッチの停止・再開、全実ジョブの処理、Azureへの実送信と翻訳品質、WALの最新状態、実際の全記事リンク、別OSでの動作は未検証。原本の画面表示はUTF-8のMarkdown・CSVかつ2 MiB以内で、それ以外も許可された通常ファイルなら元のバイトで取得できる。

MCP運用記録：`initial_instructions`は初回に1回、`context_compile`は1回、`compile_eval`は1回。コンパイル結果の評価を保存済み。
