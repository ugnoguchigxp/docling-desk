# Third-party notices

Docling Desk's own code is distributed under the MIT license in LICENSE.
Dependencies, model artifacts, fonts, and third-party components retain their own licenses.

- Docling (`docling-slim` 2.132.0, MIT) is a pinned upstream Git submodule at revision `a1c5ff2a8c5ab2bf87d7c1eb896b5bc351f51220`. Its license remains in `docling/LICENSE`. The Docker image installs it from that source (kept under `/opt/docling-source`); the wheel and sdist only declare the dependency and do not contain it.
- The Azure OCR adapter is also available as a separate package under `packages/docling-azure-ocr` (MIT). The Docker image installs it from that source.
- Wiki import/translation code was adapted from a non-public implementation by the same author (see `integrations/wiki/reference-assets.json`); retained notices are in `src/docling_desk/wiki_batch/NOTICE.md` and `licenses/` beside it.
- PyMuPDF (`pymupdf` 1.28.2) is a direct dependency used for PDF text and preview processing (`knowledge/worker.py`, `preview/powerpoint_export.py`). It is dual-licensed under AGPL-3.0 or the Artifex commercial license; this project uses it under the AGPL-3.0 terms. Its wheel bundles the MuPDF library (`libmupdf`), which is under the same terms. Anyone distributing or hosting a build that includes it (the Docker image, or a network service built from the wheel) must meet the AGPL-3.0 obligations, including offering the corresponding source. Sources: <https://github.com/pymupdf/PyMuPDF> (PyMuPDF) and <https://github.com/ArtifexSoftware/mupdf> (MuPDF); this application's source is at the `Repository` URL in `pyproject.toml`. The installed `pymupdf` metadata contains only a one-line license name, not the AGPL-3.0 text, so the full text is not shipped with this build. Whether the AGPL-3.0 conditions extend to the whole combined application is not decided here and needs human and legal review.
- The draw.io v32.5.5 read-only viewer, standard stencils, and its MathJax renderer are bundled under `src/docling_desk/resources/static/vendor/drawio/`. Upstream licenses (Apache-2.0 for the viewer and MathJax), asset terms, source version and SHA-256 checksums are retained alongside the unmodified files. The icon sets and stencil libraries carry an additional term (`img-LICENSE`, `shapes-LICENSE`, `stencils-LICENSE`): they may not be used as software assets in, distributed for use with, or incorporated into Atlassian products or the Atlassian marketplace/plugin ecosystem without explicit written permission, and derivatives made with them as reference or AI training input are included in that restriction. The term does not apply to end-user diagram output. The upstream NOTICE file, if any, is not bundled. No draw.io editor or desktop application is launched.
- Bundled AG Grid Community 35.2.1 (MIT) and the TabuLens grid port (MIT) notices and checksums are retained under `src/docling_desk/resources/static/vendor`. This copy serves the legacy screens and is separate from the AG Grid package built into the React frontend.
- The Wiki editor under `frontend/src/plate` is vendored from Plate's MIT-licensed registry (retrieved 2026-10-16); its `LICENSE` and the shadcn primitives' `LICENSE` (`ui-primitives/`) are kept in the source tree. The source tree is not part of the wheel, sdist or image; the compiled editor is.
- Fonts. The Excalidraw fonts shipped as `static/frontend/excalidraw/fonts` (Assistant, Cascadia, ComicShanns, Excalifont, Liberation, Lilita, Nunito, Virgil, Xiaolai) and the KaTeX fonts in `static/frontend/assets` are copied without per-font license files; the npm packages do not provide them. Their individual terms are not yet verified. The Docker image also installs `fonts-noto-cjk` and `fonts-liberation` from Debian; see the package copyright files under `/usr/share/doc` in the image.
- The Docker image bundles `openai-codex-cli-bin` 0.160.0, which contains the Codex CLI (Apache-2.0) together with `rg` (ripgrep) and `zsh` executables. The package has no license files for those components, so their terms and the notices of statically linked components are not yet verified.
- The Docker image is based on `python:3.12-slim-bookworm` (Debian) and installs LibreOffice, Tesseract and fonts with `apt-get`. Each Debian package keeps its copyright file in `/usr/share/doc/<package>/copyright`, and some are under GPL/LGPL terms that require offering the corresponding source. The package list including dependencies is not recorded until an image is built. The knowledge API image (`knowledge-api/Dockerfile`) is based on `oven/bun:1.4.2-slim`, adds `hono` and `zod` (MIT), and is not part of the wheel or the main image.
- Token encodings (`cl100k_base`, `o200k_base`) are downloaded by `tiktoken` on first use from `openaipublic.blob.core.windows.net`; they are not pinned or bundled in this build.
- Built frontend third-party notices are generated as `static/frontend/licenses.txt` within the installed resources. It is built from the `dependencies` of `frontend/package.json` and their own dependencies; packages that reach the bundle only through peer dependencies (currently `tailwind-merge` and the `@svta/cml-*` packages) have no entry yet.
- Model revisions and download sources are in `src/docling_desk/resources/models/manifest.json`. The application license does not grant rights to model weights or user documents.

Runtime documents and bulk verification output are excluded from source control and release archives. Synthetic fixtures are provided for tests. Dependency, model, font and image clearance is recorded per item in `supply/clearance.json`. A record with status `inventoried` is only an automated observation (declared license, distribution scope, remaining conditions) and is not a human review; only `confirmed` records with a reviewer and date count as cleared. An absent record remains unreviewed. Build and development tools (for example pnpm, Vite, Tailwind CSS, pytest, ruff) are not part of the shipped application, although `requirements-lock.txt` currently installs the Python ones into the Docker image too.
