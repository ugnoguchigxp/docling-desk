# 失敗時と再送

401は認証・期限・失効、403は許可範囲とaction、404は対象や所属を確認する。認証情報はホストが管理し、本文やツール引数に貼らない。

412は古い版。入力を保持し、最新本文とetagを取得して変更内容を見直す。409は業務codeを確認し、原文不一致・複数一致・ハッシュ不一致・再送キー衝突を区別する。ガイドのtool_guide_cursor_staleは同じガイドの先頭から読み直す。

428は必須のetagまたは再送キーを補う。413は対象数・本文量を減らす。422はスキーマ・範囲・UTF-8等を見直す。429・503は理由を確認して待機する。

書き込み前にidempotency_keyと要求内容を記録する。応答喪失時は同じキー・同じ要求の再送かget_document_operationを使う。成功結果は同じclient・actorで7日保持。期限外のoperation_unknownを未実行と見なして新しいキーで再送しない。retry_document_jobには操作キーはなく、状態を再確認して判断する。

保存後の抽出・Embedding失敗は保存失敗ではない。意味検索が使えない場合はeffective_mode・degraded_reasonsを確認。原因や条件が変わらないまま再試行を続けない。
