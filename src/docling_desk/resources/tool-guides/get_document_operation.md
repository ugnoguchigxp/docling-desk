# 通信断後の結果照会

保存応答を失った操作の結果を同じ利用者として照会する。

## 前提と引数の入手元

必要なactionはread。利用者とscopeは認証済み接続から確定する。operationと最初に送ったキーを指定。commit・update・edit・attachmentのtarget_idはdraft_id、metadataはsource_id。新規create・draftはtarget_id省略、既存文書からのdraftはsource_id。同じclient・actorが必要。保持は7日。operation_unknownを未実行と決めつけない。

## 入出力と呼び出し経路

MCPの完全な入出力スキーマと、対応する文書HTTP操作はこのガイドのschemasに含まれる。section=schemasでも取得できる。HTTPのIf-MatchはMCPではetag、Idempotency-Keyはidempotency_key。既存文書ツールは業務引数をargumentsの中へ入れる。

ホストAPIはPOST /host/tools/get_document_operationに、信頼するホストの認証とuser_id・argumentsを送る。user_idをLLMから受け取って権限を決めない。ガイドGET APIの利用者別BearerとホストAPIの資格情報を混同しない。

## 副作用と結果の確認

文書の原本や索引を変更しない。説明・本文の取得成功は、外部処理の実行や書き込み成功を意味しない。閲覧コードの承認は短期の閲覧接続を作る。
