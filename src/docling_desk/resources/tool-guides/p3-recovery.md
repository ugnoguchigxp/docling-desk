# 通信断と復旧

取り込み・差し替えはidempotency_keyを初回に記録する。同じtransfer_id・同じキー・同じ要求で再送する。成功したtransferは別キーで使い回せない。成功後はバイナリを削除し、同じ利用者・許可範囲で結果を7日保持する。現在の原本が削除・権限外になった場合は過去の成功結果も返さない。

応答を失った場合、ホストはGET /api/v1/document-transfers/{transfer_id}で結果を確認できる。転送バイトの期限は1時間。期限切れや結果未確認は未実行を意味しない。同じファイル名・内容・metadata・OCR設定を再転送し、元のidempotency_keyを使ってAPIの再送照合を行う。7日を過ぎた不明な操作を新しいキーで自動再送しない。get_document_operationはMarkdown編集用であり、バイナリ取り込み・差し替えには対応しない。

再抽出・再索引には既存APIの冪等性キー契約がない。応答が不明なときは自動再実行しない。分かっているjob_idを確認し、文書状態とホストの実行記録から次の操作を判断する。別の抽出ジョブの実行中は409 job_running。

401・403は認証と範囲、404は対象、412は最新etag、422はmetadata・OCR等の入力を確認する。転送の別利用者への流用は404、対象・基準・キーの不一致は409。文書保存後の索引失敗は保存失敗として扱わない。429・503では同じ条件のまま無制限に再試行しない。
